# M30 encrypted requests

Base: `2434563`, the committed M29 session admission and revalidation slice.

`Session.request` validates the complete typed chat, seals every supported
message, and returns an immutable HTTP request. Request contents use lowercase
hex of the client SEC1 public key, nonce, ciphertext and final GCM tag. The
prompt key comes from the established session and AAD is empty. Public
`Ciphertext.t` and `Gcm_fresh.t` have no caller-controlled constructors.

The GCM handle is distinct from the attestation challenge. Each attempt consumes
it before any subsequent check. Session aliases share one atomic state containing
both a nonce set and a reservation count. Duplicate bytes reject even from two
different handles; concurrent reservations cannot exceed 65,536. Reservations
remain consumed after failures. Separate sessions depend on independent OS
scalar generation, and no process-global key or nonce registry is claimed.

The first request API accepts only bare-string user/system contents without
message metadata. It rejects unsupported roles and media, tools, response
schemas, stop strings, cache keys, characters and enabled searches. It explicitly
enables streaming and E2EE and disables web search, scraping and X search. Exact
hex expansion is checked against the HTTP body's 4,194,304-byte cap before any
entropy draw. One plaintext is capped at 2,000,000 bytes. The outgoing template
contains empty content slots until they are replaced with encrypted frames.

## Validation

The gate runs `dunecho build`, all repository suites, public compile-fail
controls, existing differential harnesses and cross-module `zxlint`.
Final integrated `bash gates.sh`: exit 0, 37 suites green, 30 expected
compile-fail rejections, all differential oracles green and cross-module
`zxlint` clean. The three new suites passed 43/43 (`test_encryptx`), 18/18
(`test_encrypt_boundary`) and 12/12 (`test_gcm_fresh`). Existing entropy,
admission and IO suites also passed. `git diff --check` and the authored
character check passed. No live network request was part of validation.

The independent PyCryptodome oracle checks complete executable frames for
empty, zero-filled, UTF-8 and binary plaintext after checking a published
AES-256-GCM known answer. Its 19 tests reject changes to each frame component,
plaintext substitutions even with valid replacement encryption, tag-first
framing, malformed or missing rows, duplicate rows and failed executables.

The host suite compiles the production `sessionx.ml` source unchanged behind
test-only admission witnesses. Entropy, scalar multiplication, ECDH/HKDF,
GCM, chat construction and fake transport capture use the real implementations.
Race tests wait for every competing domain to reach a start barrier. Pure
preflight tests accept exactly 4,194,304 encrypted JSON bytes and reject one
additional plaintext byte, without encrypting megabytes of test data.

Independent production and host-test reviews found no concrete correctness or
security defect. No existing gate or suite was removed or made optional.

## Mutation checks

All 15 mutants compiled and failed unchanged behavioral tests in an isolated
copy. No compile-only failures counted. Baseline and restored suites passed
43/43, 18/18 and 12/12, and the restored source matched the validated tree
byte-for-byte. An initial frame-overhead mutant survived; the exact-size
preflight rows now kill it and all 15 were rerun against the final tests.

| Mutation | Named killing check |
| --- | --- |
| Skip host Fresh consumption | host encrypt: alias replay rejects before a second reservation |
| Skip session nonce reservation | host encrypt: independent handles cannot reuse nonce bytes in one session |
| Disable duplicate nonce check | host encrypt: independent handles cannot reuse nonce bytes in one session |
| Permit one extra nonce at the cap | host encrypt: nonce 65,536 is accepted and the next token burns at the cap |
| Put tag before ciphertext | seal zero16 |
| Omit client SEC1 key from frame | seal empty |
| Use nonempty AAD | seal empty |
| Bypass model equality | host request: model mismatch refuses before any entropy draw |
| Disable streaming | encrypted request body headers and log |
| Disable E2EE | encrypted request body headers and log |
| Permit enabled web search | web on |
| Relax encrypted body cap | one plaintext byte beyond encrypted body cap rejects |
| Permit repeated GCM handle consumption | GCM fresh: aliases share one use and retain only the nonce projection |
| Take the wrong entropy slice | GCM fresh: one 32-byte draw yields its exact 12-byte prefix |
| Underestimate frame overhead by one byte | one plaintext byte beyond encrypted body cap rejects |

## Limits

No successful live Venice attestation or roundtrip fixture is added. M31 owns
live interoperability, M32 response decryption and M33 response signatures.
CPU-only deployment trust, current-time admission, CRL/NRAS limitations and the
variable-time scalar implementation remain as described by M29. Secret
zeroization remains M39. Sampling options and model routing metadata are
visible. Immutable request retransmission does not reseal, but replay and
billing policy remain the caller's transport responsibility.
