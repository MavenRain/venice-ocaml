## Changes

Public Tee verification preserves full and structural expectation levels.
Session establishment requires full attestation, an E2EE model capability,
a consumed Fresh challenge, explicit time and an independently trusted
CPU-only deployment measurement policy. It revalidates the original PCK
chain and signed collateral before sampling an ephemeral scalar. Both TCB
grades must be UpToDate. Model metadata must match and present unauthenticated
GPU evidence is refused. An omitted GPU field does not mint the required
CPU-only policy.

The key schedule uses the validated attested signing key, ECDH's 32-byte
big-endian shared x, and HKDF-SHA256 with empty salt and the sixteen-byte
`ecdsa_encryption` context. The public API exposes only public key hex and
model identity. The source evidence is recorded in FACTS.md.

## Limits

There is no successful live Venice session fixture. The real Phala quote
tests signed evidence and expiry, but cannot mint an accepting Venice
attestation. No CRL or NRAS authentication, encrypted request sending or
encrypted streaming is added. GPU deployments require later authenticated
policy support. CPU-only deployment semantics and current time remain explicit
caller trust inputs. Model metadata is unsigned routing context. The
secp256k1 ladder and underlying limbs remain variable-time, and secret
zeroization remains M39. Repeated quote verification is permitted; Fresh
consumption is per session-admission attempt and per handle. Nonce-byte
uniqueness relies on OS randomness. `test/entropy_io_fakes.ml:49` is the
single raise site in the repo. Unix.openfile and Unix.read report a host
failure only by raising Unix_error, so the scripted source must raise to
drive the production guard. No lib code raises.
